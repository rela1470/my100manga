## 1. 年齢確認ゲート

**実装済み（2026-10-04, `src/ageGate.ts` + `test/ageGate.test.ts`）**。`src/index.ts` の `fetch` 冒頭、レート制限より前で `ageGate(request, url, env)` を呼び、非 null ならそれを返す。本家（`SITE_VARIANT="general"`）では即 null なので挙動は変わらない。未確認の相手はゲートの HTML を返すだけで D1 も外部 API も触らないので、書き込み枠を消費させずに弾ける。

- **同意**: Cookie `age_ok=1`（`Max-Age` 1年 / `Path=/` / `HttpOnly` / `SameSite=Lax` / https なら `Secure`）。`<form method="post" action="/age-gate">` に戻り先 `next` を隠しで持たせ、POST で `Set-Cookie` して 303 で戻す。`next` は `safeReturnPath`（`src/auth.ts`）でオリジン内のパスに限る。POST は `sameOrigin` も確かめる。JS 無効でも成立する。
- **ゲート画面**: URL は変えずに 200。静的アセットに依存しない 1 枚もの（配色は `public/styles.css` の `:root[data-site="adult"]` と揃えた値を直接書いている）。`noindex, nofollow` 付き。全年齢版（my100manga.com）への出口リンクを置いている。
- **止めるもの**: HTML を見に来たリクエスト（`sec-fetch-dest: document` / `Accept: text/html`）と `/api/…`（403 + `{"age_gate":true}`）。
- **素通りさせるもの**: ドキュメント以外（css/js/画像/フォント）、`/cover` と `/share/<slug>/<variant>.jpg`、`/robots.txt`・`/sitemap.xml`・favicon 類、`/auth/…`（Google ログインの往復）、`/admin` と `/api/admin/…`（Cloudflare Access が別途守る）、クローラ UA（`isCrawler`、`src/publicLists.ts`。ゲートを出すとインデックスも OGP も出ないため。UA 無しは素通りさせない）。
- **robots.txt**: R18版だけ `Disallow: /age-gate` が入る（`src/robots.ts`）。
- **キャッシュ**: ゲートはルート照合の前に入るので、未確認の端末が colo キャッシュ（`src/viewSnapshot.ts` の viewCacheKeys）の内容を受け取ることはない。サイト全体がゲートの内側にある前提なので、キャッシュキーにゲート状態を混ぜる必要はない。**同じ URL をゲート済み／未済で出し分ける設計に変える場合はキーを分けること**。

**残り**

- 共有画像（`/share/<slug>/og.jpg`）はゲートの外に出るので、R18版の og 画像は表紙を含めない無地のものにする（3 節・6 節）。
- **法令**: 日本国内向けは自主規制（自己申告ゲート）で足りるが、英国 Online Safety Act や米国の一部州は自己申告を age assurance として認めない。公開範囲を日本に絞る（Cloudflare の国別ブロック、または WAF ルール）かどうかは公開前に決める。→ **要判断（公開前）**

## 2. データ（`scripts/ingest.mjs`）

現状は成年向けを本体表から外して `adult_volumes` に最小列で落としている。R18版は上位互換なので、**同じダンプから別の出力を作る**。

- `--include-adult` を足す。指定時は `isAdult()` で落とさず `volumes_new` / `series_new` にそのまま入れ、`adult_volumes_new` は空のまま作る（表が無いと `findAdultIsbns` が落ちるのを避ける。`src/adult.ts` は表が無ければ空を返す実装だが、表は作っておく）。
- 成年向けシリーズの prune（`series_new_prune_adult.sql`）は `--include-adult` では生成しない。
- 適用先は R18版の D1。本家の D1 と取り違えないよう、`npm run` のスクリプト名を `ingest:remote:r18` のように分ける。
- `src/adult.ts` の `ADULT_RATING` / `ADULT_DESCRIPTION` と `scripts/ingest.mjs` の複製は引き続き揃える（node から TS を読めないため）。

本家と R18版で同じ全年齢作品のページが両方に出る（重複コンテンツ）。canonical は各オリジン自身を指すので検索側の扱いは別サイト。中身の大半はユーザのリストなので許容する。

## 4. 静的ページの差し替え

本文が実質別物になるページ（`terms.html` / `privacy.html` / `about.html` / `operator.html` / `books-guide.html` / `404.html`）は、文言置換では足りない。

**実装済み（2026-10-04, `src/siteAssets.ts` + `test/siteAssets.test.ts`）**。`public/adult/<name>.html` を置けば `SITE_VARIANT="adult"` のときそちらが配信され、無ければ本家のファイルに落ちる。`env.ASSETS.fetch` の代わりに `fetchSiteAsset(request, env, path)` を呼ぶ（静的配信・404 ページ・`view.html` のテンプレートの 3 か所）。

- 差し替えを試すのは HTML（拡張子なしのクリーン URL と `.html`）と顔まわりの画像（`og-default.png`・`favicon.ico`・`favicon.svg`・`apple-touch-icon.png`）だけ。css/js/フォントは種別で変わらないので余計な ASSETS 引きをしない。
- `/adult/…` を直接引くことは**どちらの種別でもできない**（404。URL を 1 本に保つため。これが無いと本家で `/adult/terms` が R18版の本文を返す）。
- ファイルを置くまでは全ページが本家の本文のまま出る（＝今の状態）。中身を書くのは 6 節。

- 本文の差分が「名前だけ」のページは `public/adult/` に置かず、既存の `applySiteIdentity` の置換に任せる。
- R18版の本文で書き直しが要るもの: 利用規約（成人向けの取り扱い・年齢確認・禁止事項）、プライバシー（Cookie に年齢確認の同意を保存すること）、about（何のサイトか）、運営者（本家と同一主体であることを書くか決める。→ **要判断**）、追加できる本（成年向けも対象になる）。

## 5. インフラ（R18版の Worker を立てるときの手順）

`wrangler.jsonc.sample` には `env.r18` / `env.r18dev` を入れてある（`database_id` だけ `REPLACE_WITH_...`）。実ファイルの `wrangler.jsonc` は追跡していないので、そちらにも同じものを入れる。**非継承**のキーは全部書く必要がある: `vars` / `d1_databases` / `r2_buckets` / `analytics_engine_datasets` / `durable_objects` / `migrations` / `ratelimits` / `queues` / `routes`。`triggers` は継承されるので、R18版では `{"crons": []}` で止める（売上ランキングは楽天ブックスの一般書籍なので R18版では使わない）。

作るもの・登録するもの:

- D1（`my100shunga` / `my100shunga-dev`）、R2 バケット（`my100shunga-covers*`）、Analytics Engine データセット（`my100shunga_popularity*`）、Queue 2 本（`my100shunga-share*` / `my100shunga-views*`、`wrangler queues create` が先。閲覧ビーコン側の名前には `-views` を含めること＝`VIEW_QUEUE_MARK`）、ratelimit の `namespace_id`（本家の 1001–1003 と別に 2001–2003）。
- `vars`: `SITE_VARIANT: "adult"`、`ADSENSE_CLIENT: ""`、`RAKUTEN_REFERER` は R18 ドメイン。
- secret: `ADMIN_EMAILS` / `ACCESS_TEAM_DOMAIN` / `ACCESS_AUD`（R18 ドメイン用に **Cloudflare Access アプリを別に作る**）、`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`（**別の OAuth クライアントを作る**。同意画面に出るアプリ名が本家名になるのを避けるため。リダイレクト URI は `<r18 origin>/auth/google/callback`）、`TURNSTILE_SECRET`（Turnstile のウィジェットに R18 ホスト名を登録。サイトキーと secret は同時に入れる）、アフィリ ID 各種（下の要確認次第）。
- DNS / メール: R18 ドメインで Email Routing（`admin@` / `info@` / `abuse@` → `info@harine.jp`）、SPF / DKIM / DMARC `p=reject`。
- 楽天 API の Referer 設定を R18 ドメインでも通す。

適用順は本家と同じ（`db/schema.sql` → 追加 migration → ingest → deploy）。デプロイ・remote migration・ingest は `CLAUDE.md` の通り全セッションに予告してから。

## 6. 要確認（公開前に潰す）

外部サービスの規約は「成人向けサイトでの利用」を明示的に禁じていることが多い。R18版で何が使えるかで、表紙ソースと収益の形が変わる。

- **楽天ブックス書籍検索API / 楽天アフィリエイト** … 成人向けサイトでの利用可否。**表紙の Tier1 がこれなので、不可なら表紙ソースの作り直しが要る**。
- **Yahoo!ショッピング 商品検索API / バリューコマース** … 同上（表紙 Tier2）。
- **Amazon アソシエイト** … 成人向けサイトの参加可否。
- **AdSense** … 不可（決定済み。`ADSENSE_CLIENT` は空）。
- **DMM / FANZA アフィリエイト** … 承認待ち。通れば R18版の表紙ソースと購入リンクの本命になる。
- **MADB（メディア芸術データベース）** … 成年コミックを含む公的データなので、データ自体の利用は問題なし。表紙画像だけが上記の制約を受ける。
