## 1. 年齢確認ゲート

**置き場所**: `src/index.ts` の `worker.fetch` 冒頭（レート制限の前）。`siteVariant(env) === "adult"` のときだけ働く。

**判定**:

- Cookie `age_ok=1`（`Max-Age` 1年 / `Secure` / `HttpOnly` / `SameSite=Lax` / `Path=/`）があれば素通り。
- 無ければ、**HTML を返すリクエスト**（`Accept: text/html` の GET）はゲートページを 200 で返す。URL は変えない（同意後に元のページへ戻すため）。
- **API**（`/api/`）は 403 + `{"error":"age_gate"}`。ゲート未通過の端末から書き込みが通らないようにする。
- **素通りさせるもの**: 静的アセット（css / js / 画像 / フォント / favicon）、`/robots.txt`、`/sitemap.xml`、`/age-gate`（ゲート自身の POST 先）、`/admin`（Cloudflare Access が別途守る）。
- `/cover`（表紙画像）と `/share-image`（シェア画像）は**素通りさせる**。外部サイト・SNS のカード表示に出るものなので、ゲートをかけても端末側には画像だけが届く。代わりに R18版の og 画像は中身の表紙を含めない無地のものにする（下の 3 節）。

**同意の受け方**: ゲートページは `<form method="post" action="/age-gate">`（hidden に戻り先 `next`、オリジン内パスだけ受け付ける）。POST で `Set-Cookie` して 303 で `next` へ。JS 無効でも成立させるため、localStorage ではなく Cookie。

**クローラ**: Googlebot / X / Discord など既知のクローラ UA はゲートを素通りさせて通常のページを返す。ゲートを出すとインデックスされず OGP も出ないため。UA 判定なので厳密ではないが、年齢ゲートの実務としては一般的。Cloudflare の verified bot 判定（`request.cf.verifiedBotCategory`）を併用できるなら、そちらを優先する。

**法令**: 日本国内向けは自主規制（自己申告ゲート）で足りるが、英国 Online Safety Act や米国の一部州は自己申告を age assurance として認めない。R18版の公開範囲を日本に絞る（Cloudflare の国別ブロック、または WAF ルール）かどうかは公開前に決める。→ **要判断（公開前）**。

## 2. データ（`scripts/ingest.mjs`）

現状は成年向けを本体表から外して `adult_volumes` に最小列で落としている。R18版は上位互換なので、**同じダンプから別の出力を作る**。

- `--include-adult` を足す。指定時は `isAdult()` で落とさず `volumes_new` / `series_new` にそのまま入れ、`adult_volumes_new` は空のまま作る（表が無いと `findAdultIsbns` が落ちるのを避ける。`src/adult.ts` は表が無ければ空を返す実装だが、表は作っておく）。
- 成年向けシリーズの prune（`series_new_prune_adult.sql`）は `--include-adult` では生成しない。
- 適用先は R18版の D1。本家の D1 と取り違えないよう、`npm run` のスクリプト名を `ingest:remote:r18` のように分ける。
- `src/adult.ts` の `ADULT_RATING` / `ADULT_DESCRIPTION` と `scripts/ingest.mjs` の複製は引き続き揃える（node から TS を読めないため）。

本家と R18版で同じ全年齢作品のページが両方に出る（重複コンテンツ）。canonical は各オリジン自身を指すので検索側の扱いは別サイト。中身の大半はユーザのリストなので許容する。

## 3. ドメイン・サイト名の直書きを消す

`applySiteIdentity` は HTML にしか効かないので、HTML 以外に残っている直書きを潰す。

| 対象 | 今 | どうする |
|---|---|---|
| `public/robots.txt` | `Sitemap: https://my100manga.com/sitemap.xml` | Worker で動的生成（リクエストのオリジンから組む）。R18版では `Disallow: /age-gate` を足す |
| `public/sitemap.xml` | 本家 URL 9 本を直書き | 同上。オリジン＋パス一覧から組む |
| `src/shareImage.ts` | 見出し「My 100 Manga」固定、`COLOR` がブルー固定 | `site(env)` から名前を取り、`COLOR` を種別ごとに持つ（配色は `public/styles.css` の `data-site="adult"` と揃える）。見出しは `My` ＋ 色違いの `100` ＋ 残り、と 3 つに割って描いているので、名前を単純に差し替えるだけでは済まない（`My 100 ◯◯` の形を前提に最後の語だけ差し替えるか、SiteConfig に分割済みの名前を持たせる） |

## 4. 静的ページの差し替え

本文が実質別物になるページ（`terms.html` / `privacy.html` / `about.html` / `operator.html` / `books-guide.html` / `404.html`）は、文言置換では足りない。

**方式**: `public/adult/<name>.html` を置き、`SITE_VARIANT="adult"` のときはそちらを優先して配信する（無ければ本家のファイルにフォールバック）。`assets` は `run_worker_first: true` なので、`env.ASSETS.fetch` に渡す URL を差し替えるだけで実現できる。画像（og / favicon）も同じ仕組みに乗る。

- 本文の差分が「名前だけ」のページは `public/adult/` に置かず、既存の `applySiteIdentity` の置換に任せる。
- R18版の本文で書き直しが要るもの: 利用規約（成人向けの取り扱い・年齢確認・禁止事項）、プライバシー（Cookie に年齢確認の同意を保存すること）、about（何のサイトか）、運営者（本家と同一主体であることを書くか決める。→ **要判断**）、追加できる本（成年向けも対象になる）。

## 5. インフラ（R18版の Worker を立てるときの手順）

`wrangler.jsonc.sample` には `env.r18` / `env.r18dev` を入れてある（`database_id` だけ `REPLACE_WITH_...`）。実ファイルの `wrangler.jsonc` は追跡していないので、そちらにも同じものを入れる。**非継承**のキーは全部書く必要がある: `vars` / `d1_databases` / `r2_buckets` / `analytics_engine_datasets` / `durable_objects` / `migrations` / `ratelimits` / `queues` / `routes`。`triggers` は継承されるので、R18版では `{"crons": []}` で止める（売上ランキングは楽天ブックスの一般書籍なので R18版では使わない）。

作るもの・登録するもの:

- D1（`my100shunga` / `my100shunga-dev`）、R2 バケット（`my100shunga-covers*`）、Analytics Engine データセット（`my100shunga_popularity*`）、Queue 2 本（`my100shunga-share*` / `my100shunga-views*`、`wrangler queues create` が先。**`VIEW_QUEUE_PREFIX` を直してから**）、ratelimit の `namespace_id`（本家の 1001–1003 と別に 2001–2003）。
- `vars`: `SITE_VARIANT: "adult"`、`ADSENSE_CLIENT: ""`、`RAKUTEN_REFERER` は R18 ドメイン。
- secret: `ADMIN_EMAILS` / `ACCESS_TEAM_DOMAIN` / `ACCESS_AUD`（R18 ドメイン用に **Cloudflare Access アプリを別に作る**）、`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`（**別の OAuth クライアントを作る**。同意画面に出るアプリ名が本家名になるのを避けるため。リダイレクト URI は `<r18 origin>/auth/google/callback`）、`TURNSTILE_SECRET`（Turnstile のウィジェットに R18 ホスト名を登録。サイトキーと secret は同時に入れる）、アフィリ ID 各種（下の要確認次第）。
- DNS / メール: R18 ドメインで Email Routing（`admin@` / `info@` / `abuse@` → `info@harine.jp`）、SPF / DKIM / DMARC `p=reject`。
- 楽天 API の Referer 設定を R18 ドメインでも通す。

適用順は本家と同じ（`db/schema.sql` → 追加 migration → ingest → deploy）。デプロイ・remote migration・ingest は `CLAUDE.md` の通り全セッションに予告してから。

## 6. 要確認（公開前に潰す）

外部サービスの規約は「成人向けサイトでの利用」を明示的に禁じていることが多い。R18版で何が使えるかで、表紙ソースと収益の形が変わる。

- **楽天ブックス書籍検索API / 楽天アフィリエイト** … 成人向けサイトでの利用可否。**表紙の Tier1 がこれなので、不可なら表紙ソースの作り直しが要る**。
- **Yahoo!ショッピング 商品検索API / バリューコマース** … 同上（表紙 Tier2）。
- **Amazon アソシエイト** … 成人向けサイトの参加可否。
- **AdSense** … 不可（決定済み。`ADSENSE_CLIENT` は空）。
- **DMM / FANZA アフィリエイト** … 承認待ち。通れば R18版の表紙ソースと購入リンクの本命になる。
- **MADB（メディア芸術データベース）** … 成年コミックを含む公的データなので、データ自体の利用は問題なし。表紙画像だけが上記の制約を受ける。
