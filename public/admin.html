シリーズ名の修正

閲覧者が「シリーズ名が違う」と通報したシリーズの一覧です。上流マスターのタイトルが壊れている （例: 「ハレグゥ」が「ｖ」で取り込まれている）場合に使います。かな読み・収録巻のタイトルを 正しい名前のヒントとして併記しています。「名前を修正」で正しい名前を入力すると 全ての閲覧者の検索/詳細表示に反映されます（再取り込みでマスターが戻っても 上書きは維持されます）。誤報なら「却下」で通報だけ消します。

シリーズの結合

上流マスターで同じ作品が複数のシリーズ（C-id）に分かれているものを 1 つにまとめます （例: 「One piece」SJR 版が 1巻だけ別シリーズ）。「残す」を選んで「結合」すると、 全ての閲覧者の検索・巻一覧・リスト表示で 1 シリーズとして扱われます （再取り込みでも維持され、「結合済み」から解除できます）。 「自動検出の候補」は名前・著者・出版社・レーベルが同じで巻番号が重ならない組です。 新装版/通常版のような別の版なら「却下」してください。 ID が「G…」のものはシリーズに属さない巻のまとまり（書名＋著者）です。結合すると巻を 残す側のシリーズに紐付け、残す側が「G…」なら独自シリーズ（「U…」）を作ります （「巻の紐付け」から解除できます。名前は名前修正で直せます）。 「分離」は逆に、1 つのシリーズに混ざった別の版（例: キン肉マン C261524 の復刻版）を ISBN を選んで独自シリーズへ移します（再取り込みでも維持され、「巻の紐付け」から解除すると元のシリーズに戻ります）。 「分離の依頼」は閲覧者の「別の版が混ざっている？」で、依頼された巻を選んだ状態で分離の画面を開けます。

本のタイトルの修正

閲覧者が「本のタイトルが違う」と通報した巻（ISBN 単位）の一覧です。巻の schema:name は シリーズ名の繰り返しですが、表記ゆれ分割などで一部の巻だけ変なタイトルを背負うことが あります。所属シリーズで最多の巻タイトルをヒントとして併記しています。「揃える」で そのシリーズで最多のタイトルに統一、または「修正」で正しいタイトルを 手入力すると、全ての閲覧者の巻一覧/詳細表示に反映されます（再取り込みで マスターが戻っても上書きは維持されます）。誤報なら「却下」で通報だけ消します。

表紙の修正（ユーザが選び直した表紙）

リスト編集の「表紙を変更」で、ユーザがキャッシュと違う表紙を選んだものの一覧です。選んだ表紙は そのユーザのリストにしか反映されていません（＝本人のぶんだけ）。現在の表紙と提案された表紙を 見比べて、提案が正しければ「承認」で表紙キャッシュを上書きし全体に反映します （同じ本を載せた他のリストやシリーズ閲覧にも波及。同 ISBN の他の候補は解決済みとして消えます）。 誤りなら「却下」で提案だけ消します。ISBN をクリックすると外部サイトで実物を確認できます。 作品名・巻数をクリックすると、そのシリーズの巻一覧を表示して実物を確認できます。

表紙キャッシュ

「No Image」は書影が見つからず確定キャッシュした本です。削除すると次回アクセス時に再探索されます （新しく書影が追加された本の拾い直しに有効）。「全キャッシュ削除」は R2 のトリム済み表紙画像も消すので、 次回アクセス時に再探索・再トリムされます（表紙トリムのクリーン再テスト用）。

トリム済み表紙画像（R2）

Yahoo!ショッピングの正方形表紙を白帯トリムして R2 に保存した画像です。ここで削除すると、 D1 の表紙キャッシュは残したまま R2 の実体だけを消します（次回アクセス時に同じ元画像から 再トリムして入れ直されます）。表紙トリム処理そのものの再テストに使います。

補完キャッシュ（ライブMADB巻補完）

シリーズごとにライブMADBから補完した新刊巻をキャッシュしています（TTL 30日）。 「該当なし」は補完巻が見つからず確定キャッシュした行で、削除すると次回アクセス時に再取得します （上流に新刊が追加された時の拾い直しに有効）。

売上ランキング

楽天ブックスのコミック売れ筋上位 300 件を毎日 05:00（JST）の Cron で取得し、作品ごとに集計しています（公開ページ /sales-ranking）。 「今日の分を取得」は Cron を待たずに今日の分を取ります。毎日同じ時刻の順位で揃えるため、手動で取った分はその日の 05:00 の Cron で置き換わり、Cron が取得済みの日は手動では取り直しません。 「再集計のみ」は取得せず、作品名の付け直しと集計だけを行います（作品名・寄せ先の判定を直した後や、シリーズを結合した後に）。

発行部数ランキング

英語版ウィキペディア「List of best-selling manga」（累計 2000 万部以上の約 200 作品）から取り込んだ累計発行部数です（公開ページ /circulation）。 取り込みはローカルで node scripts/wikipedia-circulation.mjs を実行して db/circulation-data.sql を作り直し、それを D1 に流します（手順は db/MIGRATIONS.md）。 「再集計」は取り込み済みのデータに対して、作品名 → シリーズの寄せと表紙を付け直します（取り込み直した後・シリーズを結合した後に実行してください）。

寄せ先の指定

作品ごとの寄せ先（巻一覧を開く先）です。既定では自動照合の結果が「サジェスト」として入っていて、 間違っているものだけここで直します。「変更」でマスタのシリーズを検索して選び、本編が収録されていない作品は 「寄せない」にします（検索結果へのリンクだけになります）。「戻す」で指定を外すと自動照合に戻ります。
「サジェストを取り込む」は、指定の無い作品を自動照合して埋めます（既にある指定は変わりません）。 マスタを取り込み直したあと、新しく収録された作品を拾うのに使ってください。 サジェストのままの行も付け直したいときは POST /api/admin/circulation/suggest?overwrite=1（手動指定は残ります）。

キャッシュ暖機

人気のある作品の巻から順に表紙（covers）とあらすじ（book_meta）を先に取得しておき、最初の閲覧者を待たせないようにします。 楽天 API の枠はサイト全体で約 1 件/秒なので、発行部数ランキングぶん（約 6 千巻）でおよそ 2 時間かかります。 このページを開いたまま「開始」で回し続けられます（閉じると止まりますが、続きから再開できます）。 長時間まとめて回すときは手元から node scripts/warm-cache.mjs を使ってください。

楽天データ（あらすじ・作者・出版社）

本の詳細ポップアップ用に、楽天ブックスから取得したあらすじ（itemCaption）・作者・出版社・発行日を ISBN ごとにキャッシュしています（出版済みの本のメタデータは不変なので永続キャッシュ）。 「あらすじ無し」は楽天にエントリはあったがあらすじが無く確定キャッシュした本です。削除すると 次回ポップアップを開いた時に楽天を引き直します（後からあらすじが付いた本の拾い直しに有効）。 あらすじをクリックすると全文を表示します。

DB の初期化（マスターデータ以外を全削除）

MADB 由来のマスターデータ（シリーズ・巻・メタ情報）は残したまま、それ以外の テーブルを全て空にして開発用に初期化します。削除対象は次のとおりです:

  • 公開リスト（lists）と追加イベントログ（list_item_events）
  • 各種キャッシュ（表紙・楽天データ・補完）
  • ユーザ投稿の修正・通報・各種上書き・表紙の修正
  • 自由入力の通報・公開の監査ログ
  • R2 のトリム済み表紙画像（yahoo/*.jpg）

この操作は元に戻せません。
